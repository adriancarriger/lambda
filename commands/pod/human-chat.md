# From {owner}, directly: $ARGUMENTS

{owner} typed this into your pod's thread. Your answers reach {owner} only through `lambda pod reply` — never your terminal.

- Ignore it if this `[m:…]` id was already handled (re-delivery after a restart).
- Reply with `lambda pod reply --ask "<text>"` **only if you need an answer** — that puts it in {owner}'s inbox as "Your turn". Everything else (acknowledgements, "got it, carrying on", status) is `lambda pod reply --fyi "<text>"`: it stays in the thread and never pulls {owner} back in. If the message was "Done — carry on" / "nothing more to add", do not ask anything — at most one `--fyi`.
- Lead with the answer. A short answer stays short (1–3 sentences); anything longer takes the scannable shape in your dev instructions, "How your messages look" — a bold answer line, then short labelled lists, never one long paragraph. If you need to look something up, reply `--fyi "checking <what>"` first, then reply again with the result.
- Your reply renders as markdown (your dev instructions, "How your messages look"); `[Image: /path]` lines in the message are images {owner} attached — open them with Read.
- **Telling {owner} about a prototype** (a design question, a re-design, "show me a prototype"): put the line `lambda design snapshot` printed (`[Prototype: <slug> v<n>]`) **on its own line** in your `lambda pod reply`. The inbox turns it into a card {owner} can try; a claude.ai link alone can't be tried there. A freeform pod designs as `/freeform` says.
- **Asking {owner} to decide?** Context, Problem, Options (lettered) and a Recommendation — your dev instructions, "Asking {owner}". Never a bare "A or B?".
- If {owner} made a decision, record it: `lambda pod decide "<decision>" --quote "<the exact words>"` and mention it in your reply ("Recorded: …").
- **An open checkpoint is a live doc.** When something {owner} says changes what's on its card — a proposed ticket, a triage row, a screen, the plan, the changes list — edit that part in the card's own file (the one you passed to `lambda pod checkpoint post`: `proposal.json`, your plan / changes / screens / judgements file) **in place, before you reply. Don't re-post.** Then run `lambda pod checkpoint refresh $POD_ID --cp <n>`: it re-reads the file with the same checks as posting and updates the card. Record the decision and reply with what changed ("Updated the card: ticket 3 now …"). If the refresh says your edit **didn't pass its checks**, fix the file and refresh again. An open _question's_ sections change with `lambda pod question edit`.
- **{owner} names a ticket's lane** ("2 is a quick fix", "make 3 an investigation"): record it with `lambda pod decide`, then put it where it will stick. A ticket on an open split proposal: set its `lane` in `proposal.json` (`"quick-fix"` / `"investigation"`; remove it for a normal build) — the card shows the tag. A batch's triage row: its `lane` (and `laneWas`) in the plan file. A ticket that already exists: `lambda tickets update <id> --label <lane>` now, and bring the ticket into that lane (pod-phase, "tickets"). Not proposed yet: keep the decision — the split proposal sets `lane` from it.
- Anything {owner} says about the idea in phase 1 belongs in `intent.md` under **{owner}'s words (verbatim)**.
- **A question from {owner} is answered as a conversation:** reply `--ask` and end with an open door ("Anything you'd change before I go on?"), so it lands as "Your turn" and can be talked through. In **phase 1 (Shape)** the pipeline waits while that's open — the manager won't move past Shape until the reply has nothing more to ask, or "Done — carry on" is pressed.
- **When a phase-1 talk settles** (the reply needs no further `--ask` from you, or it said "Done — carry on"): after your `--fyi`, run `lambda pod send $POD_ID manager "[dev] The owner's questions are settled — Shape can finish."` so the pipeline picks up straight away.
- **A freeform pod** (`lambda pod status $POD_ID` says `mode: FREEFORM`): it's a conversation — every reply is `--ask` (see `/freeform`), and nothing in the pipeline waits on it. When it's finished, offer to close it, and close it with `lambda pod done $POD_ID` if {owner} agrees (see `/freeform`).
- **{owner} agrees part of this should be its own Lambda** (its own epic, a side topic — not a triage pull-out, which has its own step): start it yourself, never ask for it to be pasted anywhere — `lambda pod new <slug> --spinoff <the [m:…] id of the message agreeing> --text "<the ask in {owner}'s words, then where this chat left it and any notes file to read first>"`. It starts as a freeform chat, linked to this one; say in your reply that it's started.
- **{owner} asks to skip a stage** ("skip research", "no UX review for this one"): `lambda pod skip $POD_ID <stage id> --quote "<the exact words>"` (stage ids: `lambda pod skip $POD_ID x` lists them), then reply `--fyi` saying what's skipped.
